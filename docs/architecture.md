# Architecture

The edge Worker accepts only `GET /healthz` and `POST /v1/evidence`. `parseIngressRequest()` is the sole incoming-request capability boundary: it directly reads only content type, declared content length, and required idempotency key; it does not inspect request metadata or request-identifying headers. It produces a closed parsed DTO, so application and coordinator logic never receive an incoming request capability. The Worker bounds the body, parses the closed contract, and forwards a sanitized reconstruction to one globally named Durable Object.

`EvidenceCoordinator` serializes normal-instance reconciliations with a short-lived in-memory queue, while durable state makes recovery safe after a restart. Its SQLite table holds a SHA-256 idempotency-key digest, expiry, `pending`/`in_flight`/`completed` status, fixed aggregate target, and desired Git blob SHA. It never stores the evidence envelope. A successful write marks the digest completed for its full 24-hour TTL, so later model updates cannot turn a retry into another aggregate write. Immediately before every external PUT, the descriptor becomes durable `in_flight`; any abort or transport failure therefore fails closed until reconciliation proves it landed. Only a known 409 whose bounded reconciliation proves the descriptor absent returns to `pending` for a later retry.

GitHub calls have a 10-second abort deadline covering bounded response-body consumption. The Durable Object does not hold `blockConcurrencyWhile()` across network I/O; conditional blob writes and the bounded conflict retry preserve aggregate consistency while keeping the DO responsive. SQLite writes establish the corresponding alarm in the same synchronous storage turn, so a reset cannot leave a persisted digest without an expiry wakeup. Its alarm wakes it at the earliest TTL expiry to purge idle idempotency state and schedule the next expiry.

The sink reads and writes only the fixed Commons repository and model aggregate path. Each Contents API write supplies the current blob SHA and a fixed service committer. New aggregates are capped at 128 atoms and 48 KiB: their worst-case base64 Contents response is below the 128 KiB client response cap (and GitHub's 1 MiB Contents file limit). Read compatibility remains wider: a prior valid aggregate within the response bound may exceed the forward cap, and a matching submission can merge it losslessly without adding cardinality. A legacy aggregate cannot grow to new dimensions. Reconciliation reads at most three history pages of 12 commits, validates that GitHub honors that page size, and makes at most 40 GitHub requests (one current read, three history reads, and 36 historical-content reads), below the 50-subrequest free-plan budget. It aggregates allowed atom counts; it does not publish a contributor identity or raw request envelope.
